# 同一动作资源不代表同一次请求

Live2DCanvas的playMotion原先只冻结modelRevision。异步SDK返回false时，先按动作组和索引清状态，再交给上层onStarted。上层虽有motionRequestRevision检查，副作用却已发生：同模型重复播放同一动作时，旧失败会清掉新动作的显示状态。

修复在底层settle入口联合核对模型修订、表演请求修订和单次播放序号，失配直接返回。取消/回落会增加既有motionRequestRevision；普通底层试播和待机也通过新播放序号互相区分。当前失败仍清理自身状态并通知调用方，不吞掉当前失败。

回归测试提取生产playMotion函数，控制startMotion Promise的完成顺序；先以仅模型检查复现旧行为，再验证重复同资源旧失败、取消、新表演、换模型、迟到拒绝及当前失败。真实SDK工作台另外验证两角色正常动作与显式取消回落；这不是人为注入网络慢加载的端到端实录，也不证明SDK底层所有预约竞态都已覆盖。

没有新增Runtime、协议或资源。不用增加动作量弥补状态归属错误，也不根据此测试宣称延迟改善。
