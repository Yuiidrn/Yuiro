# 表情选中不代表模型真正执行：眨眼后写覆盖

抽查Hotaru默认候选时，exp_bsmile01的UI状态正确，但图上仍睁眼。资源明确EyeOpen Multiply 0，等待淡入完成后，在原生Cubism Model.update边界采到的值仍0.393–1。结合安装SDK源码确认顺序为动作→save→表情→自动眨眼→其他通道→绘制，后写眨眼覆盖了表情眼睛。

修复位于Embodiment的SDK实例适配层，不更换Runtime或修改node_modules：包装实例update捕获dt，包装motion update记录原返回值，在afterMotionUpdate事件里先执行原眨眼，再让SDK原有表情合成；原后写眨眼跳过。动作正在更新时不额外自动眨眼，保留SDK规则。每帧仍一次眨眼，函数返回/this/时间单位保留；模型卸载解除监听并恢复原方法，重复装配与清理有保护。

在正确执行表情以前，不宜靠改文件排序或挑另一张图来“修复自然度”。本轮未改配置或语义候选，先补真正的参数写入证据。修复后Hotaru bsmile稳定双眼0，Hiyori happy稳定0.55，中性/回落均继续0–1眨眼；再用两角色真实SDK动作+表情+合成口型验证绘制前口型0.7、不被覆盖，释放后为0。

源码专项、类型/构建与原生参数/图片证据见[验收记录](../plan/2026-11-10-expression-blink-order.md)。图片与core数值证明该问题修复，不证明全部资源语义或真人声学同步。当前依赖的Cubism4更新事件与方法属于SDK边缘契约，升级pixi-live2d-display时必须重新验证顺序和这些实际参数；不应将适配器视为任意未来SDK都自动兼容。
