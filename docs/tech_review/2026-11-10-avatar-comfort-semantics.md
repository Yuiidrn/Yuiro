# 表现悲伤不等于安抚用户

共享词表live2dInfer把sad/cry/tear动作自动归comfort。此前真实动态抽查已发现Hotaru哭泣/低落资源，但安抚适配尚未审定；继续让它们作为默认安抚候选，会把角色自身情绪与对用户的交互行为混为一谈。

修复只删除三个自动动作推断，保留comfort/pat/hug以及sad表情推断。真实Hotaru资源中7个动作退回未映射，不删除资产；明确group#index及后端角色档案的具体覆盖仍优先。缺失槽位沿用既有“只演表情”回退，避免为了动作覆盖率随机凑资源。

确定性测试直接读取两套model3及motion3元数据，调用生产推断和resolver，记录候选前后差异、显式选择仍有效。重启项目Electron主进程后，通过真实inspectPetModel读取新清单；本地预览再验证资源播放/取消。缓存位于主进程，仅刷新renderer不会重新加载共享词表，因此此次确实重启了壳。引擎未重启，捕获保护使用正常启动配置，未打开麦克风或调用云端。

范围限制：当前performance库comfort仍选择sad表情槽，这可表达共情但并未完成全部视觉语义审定；本补丁不声称所有安抚演出已自然。用户可在角色档案明确映射经过审定的动作，后续应以真实演出反馈决定，而不是恢复按悲伤文件名自动等同安抚。
