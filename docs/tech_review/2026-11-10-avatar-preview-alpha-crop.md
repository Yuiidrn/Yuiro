# 从模型画布边界改为可见轮廓头像取景

动态资源抽查发现Hotaru的头像只占预览底部小块：原取景以模型layout顶部34%为头部，但该资产画布留白很大，几何顶部不等于可见人物头部。只修全身缩略图没有覆盖头像路径，静帧数量齐全也无法保证表情可辨。

修正沿用capturePreview：先画180×240全身临时预览，在其alpha>20的像素上找可见边界，取人物上部的方形区域，再把区域反算回原始canvas像素坐标输出180×180头像。低分辨率图只用于定位，实际颜色取自原始画布，避免缩小后再次放大损失细节。透明图返回空头像，裁剪保持画布边界内。只在截图时运行，不添加动画帧读回。

表情缓存单独升级v3-head，动作缓存保留v2，兼顾修正生效与已有动作图复用。头像取景使用轮廓几何，不能称为人脸识别；手举过头、夸张动作和未来不同体型资产仍需专门验证。

新增alpha留白/空图测试，保留原局部坐标和DPI测试；工作台预览调度专项及类型/构建通过。真实本地舞台六段完整周期+18帧、原始前后图和配置一致性记录见[验收报告](../plan/2026-11-10-avatar-dynamic-resource-review.md)。观察到Hiyori单击短动作与Hotaru挥手的正向表现，但哭泣/tear是否适合安抚仍未通过审定，没有为追求“更生动”自动扩张动作映射。
