# 首句优化：修复短前缀阻塞，而非碎片化朗读

流式_agent_reply的_drain旧版总取最早完整句界，发现长度不足就break。当LLM先生成“嗯。”，再生成完整解释时，每次仍命中同一过短句界，直到LLM结束flush才发出声音文本。这会让“首句优先”在常见语气词开头失效。

本次给sentence_boundary增加min_len（默认1保持其他调用行为），直接寻找第一个达到累计长度的安全句界。短前缀因而与后续完整句合并，不会独立触发一次TTS。_drain首句仍6字，交付后同一token块内也立即恢复12字阈值。URL中的问号/分号仍受保护，文字拼接不丢失、不重复，未强切无标点词组，内部中文及出口翻译不变。

验证直接编译生产嵌套函数和实际_agent_reply，避免导入main启动模型；事件驱动场景在后续token仍阻塞时确认首句已交付，取消后不补发。固定延迟token回放另采每种情况5次，before/after原始JSON保留，测量对象是文本交付，不是声学TTFA。短前缀中位约343→42ms，普通开头约21ms保持；数值取决于合成输入节奏，不能外推成供应商提速比例。

WS预连接实验独立于生产：连接先于模拟1.5秒后的文本就绪，两次均先完成握手，文本就绪后首个等价480ms PCM约541/520ms。当前样本支持将握手与生成重叠的可行性；不代表同网络/同服务器负载下必然胜过暖HTTP。实际LLM、中文→朗读语言转换尚未接进这条实验链，不能直接把此数据写成端到端指标。

后续如接入WS，建议按单轮回复持有连接和上下文，而不是每句新握手；在LLM开始时异步连接，翻译后的句子依序喂入，取消/换角/无输出时关闭并join。继续继承现有SpeechOwner、session/generation及播放队列边界，不用跨角色永久会话或重复合成兜底掩盖问题。当前HTTP保持默认。
