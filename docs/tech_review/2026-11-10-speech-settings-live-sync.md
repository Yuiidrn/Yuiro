# 设置镜像需要通知与迟到响应边界

后端已经在配置PUT时更新运行中VoicePipeline，但桌宠前端只在启动/重连/开麦时读打断设置。调试台保存后，输入回调闭包里的bargeInEnabled ref可能一直停在旧值。不能靠重新开麦掩盖缺少跨窗口刷新。

本次沿用已有同源storage机制发轻量提示，内容只有角色和随机nonce；收到后回读引擎。没有把实际配置、声音或密钥写入新缓存，没有另建EventBus或修改内核事件协议。成功保存和重载才通知，读请求不通知，因此没有通知环路。

反向由聊天坞快捷开关通知DevApp，无草稿时刷新，编辑/保存/换角时不覆盖。双端读取都需要请求序号、角色与存活检查；快捷写入还捕获角色revision，在异步密钥与HTTP返回后重验，避免旧角色状态提示和通知污染当前角色。

可控生产函数测试覆盖乱序结果、坏通知、卸载、旧角色与保存失败。实际同一页面八次双向变化都同步，原config sections完整恢复，受控dirty标记阻止Dev回读。详见[验收记录](../plan/2026-11-10-speech-settings-live-sync.md)。这证明真实API/窗口/ref同步，不等价于在真人麦克风开启时测过声学打断；后者仍待用户准备答复。

初版诊断找不到未挂载的聊天坞控件，修正测试入口而非改产品显示策略。配置写入未开始，不能因此声称产品UI故障；同样不能让重载页面把真正的热更新缺失掩盖掉。
