# 调试台 UI 自定义补齐复盘

实施和验收见 [UI 自定义报告](../plan/ui-customization-refresh.md)。范围仅为 Electron/Vue 显示层，延续现有 Runtime、角色隔离与播放器归属。

## 显示参数必须连到真正的组件

拆窗和播放器接入后，旧调试台仍主要控制宽度/透明度/偏移。字号、固定高度、来源摘要、音乐按钮排布散落在 CSS 中，调试台的功能岛说明也已过时。本轮保留旧偏好键，新建受限显示 schema，避免迁移旧设置或直接引入任意 CSS。

回复抽成 ReplySurface，结果继续用 ResultCard；实际独立窗口与调试台预览共用组件和样式计算。预览父组件只响应本地 demo 事件，没有接入窗口动作/Engine，所以点击示例歌曲或链接不会真实执行。位置仍由原 main coordinator 决定，不把模型跟随、边缘避让复制到预览里。

来源可选择独立尺寸/字号，默认继承；播放器按钮可纵排，不能隐藏选择或暂停语义。普通卡片时长可热更新，官方播放有归属时仍保留控制卡。分组恢复分别处理旧偏好和新 schema，不能把“重置来源摘要”变成“重置所有界面设置”。

## 生命周期问题比滑杆更容易漏掉

实测专门增加“离开 UI 页→其他窗口调整→返回”的场景，发现 VueUse 的 storage 事件注册通过 mounted 回调可能落在组件 scope，即使数据 watch 使用独立 effectScope，监听仍会在组件卸载时终止。

修正为模块加载期间在独立 scope 内创建窗口级偏好，绕开组件 mounted 的生命周期绑定；HMR 时统一释放 scope。页面组件可以反复挂载/卸载，而同步持续存在。跟随桌宠主题还需通过同一响应式偏好更新同窗口预览，不能只依赖“别的窗口才收到”的原生 storage 事件。

新 schema 只保留已知字段，对类型、NaN/Infinity、字号、宽高、间距和时长设边界。来源宽度与原生窗口上限一致；圆角和字体通过数值/CSS 变量计算，不接受用户脚本或任意样式字符串。新参数不扩大执行或权限层。

## 验收分层

- Node 直接运行生产 schema/样式/布局函数，覆盖损坏或部分持久值、幂等归一化、主题、继承、有界 gap、模型/面板不交叠与官方控制卡不自动消失。
- 运行中的 Vue/Electron 验证实际数值输入、跨窗样式、source 原生尺寸、renderer 重载、分组重置、当前时长变化及设置页卸载后继续同步。
- Hiyori/Hotaru 切换走真实引擎，确认共享显示偏好与内容清理；没有执行聊天、联网检索或音乐播放，不用这些样本声称完成了新的音频验收。

诊断还区分了两类测试问题：恢复偏好应先还原响应式 refs，再还原键的存在性，不能只改同窗口 storage 造成设置页显示残留；混合 DPI 下 340 px 可能量成 341 px，原生尺寸判断允许 1 px 向上取整。最终验收恢复原偏好，不把测试排版留在用户界面。

前端类型检查、生产构建及既有独立窗口/轮廓/C0 检查通过。未改 Python 引擎，没有扩大回归到无关后端或另起一套 Runtime。暂缓角色专属 UI 配置、任意 CSS、设置导入/导出和真实桌面预览覆盖层；这些需要单独的产品与安全边界。
