## 三、必须在实施中守住的红线（从设计文档提炼）

## 四、第四轮：用户实测反馈（日记独立窗口 + 联网入口修复）

### 4.1 日记改为**独立窗口**（原为聊天坞内嵌）

**决策依据**：日记输入**不走 AgentLoop** 是一条硬边界（日记正文里的"记事本/微信"会被
预路由当指令真的去开应用）。内嵌在聊天坞里，这条边界对用户**不可见** —— 用户会以为
自己在"跟她说话"。物理分离后：边界一眼可见、草稿区有足够空间、语音与键入都自然。

| 改动 | 文件 |
|---|---|
| 功能岛入口：**日志 → 日记**（右列中间；日志仍在调试台页签） | `components/BracketMenu.vue` |
| 点击分账 → `openDiary()` | `renderer/src/App.vue` |
| 多入口构建 | `electron.vite.config.ts`（`diary: src/renderer/diary.html`） |
| 窗口创建 + IPC | `main/index.ts`（`createDiaryWindow` / `diary:open`） |
| 桥接 | `preload/index.ts`（`openDiary`） |
| 窗口应用 | `renderer/diary.html` + `src/diary/main.ts` + `DiaryApp.vue` |
| 语音采集 | `src/diary/useRecorder.ts` |

窗口复用**同一套 `diary:*` 协议**（草稿/审阅/处置/吐槽/总评），因此与聊天坞入口
看到的是**同一份草稿**（引擎侧 `DiarySession` 是单一权威）—— 不存在两套状态。

### 4.2 ★ 语音日记：新端点，**不复用 `/ws/audio`**

`/ws/audio` 是**对话链路**（VAD→ASR→LLM→TTS）。日记正文走它会出现三种事故：
预路由把正文当指令、正文进 history 污染记忆、她出声打断心流。语音日记只需要
「音频 → 文字」，故新增：

```
POST /api/diary/transcribe      # body: 16kHz/mono/int16 LE PCM（裸二进制）
→ {ok, text, duration_ms}
```

- 直接调 **`voice_pipeline._asr`**（模型常驻，不重复加载；`_test_asr` 那样每次 new
  一个 provider 会慢到不可用）；
- 前端 `useRecorder` 只采集 + 重采样 16k，采完 POST；
- **判断规则**：复用能力时先问"我复用的是它的**能力**，还是它整条**链路**？"
  复用链路就会连带它的语义（对话、记忆、出声）——日记要的只是 ASR 能力。

### 4.3 联网开关：图标不显示 + 点击无反应（两个独立 bug）

+「聊天框里日记功能就可以下了」+「语音识别到的文字草稿要落入编辑区」。

| 项 | 前 | 后 |
|---|---|---|

| 交互 | 独立 `diary:*` 通道，**完全不进对话**（心流优先、默认静音） | 每写一段 → 草稿 **+ 作为聊天输入让她接话**（开关默认**开**，可关成"纯记录"） |

### 4.6 ★ 转发必须绕主进程（不能日记窗口自己发 `chat:user`）

原因（两条都是硬事实）：
1. 引擎 `chat:assistant` 只回**发起的那条连接**（`await ws.send_json(...)`）；
2. `_control_conns` 按 session 存**单个**连接（`_control_conns[session_id] = ws`，新连接顶掉旧的）。

→ 日记窗口自己发 `chat:user` 会**开一个新 session**：回复接不上桌宠的 history、
**也显示不到桌宠窗口**（气泡/口型/TTS 都在那边）。
→ 故路径为：日记窗口 → `diary:relay-chat`（主进程）→ `pet:relay-chat`（桌宠窗口）
→ 桌宠用**自己的 session** 发出。

### 4.7 联网开关"引擎未连接"：**失效状态被永久钉死**

现象：日志 `[search] 联网检索不可用：引擎未连接`，但引擎明明在跑。

根因：`loadSearchStatus()` **只在 `onMounted` 查一次**。桌宠窗口通常先于引擎就绪 ——
那一刻 fetch 失败 → 落到 catch → `webSearchHint` 被钉死成"引擎未连接" → **此后再不重试**。

修复：在 **WS `onopen`** 里也刷新一次（每次连接/重连都会刷），引擎确定在线才做判定。

**★ 判断规则**：**"失败"是一种状态，不能一次判定就永久缓存**。凡"探测外部依赖是否可用"
的逻辑，都要绑定到**连接生命周期**（open / 重连 / 显式刷新）上；否则依赖晚起或重启后，
界面会永远停在错误态。这与"不能静默失效"是一体两面 —— **既不静默，也不把失败钉死**。

**验证（第二轮）**：`vue-tsc --noEmit` 0 错；`electron-vite build` 通过（`diary.html` 产出）。

### 4.8 联网检索"还是不可用"：**两个叠加缺口**（CSP + 无配置入口）

用户第二轮反馈依旧是 `联网检索不可用：引擎未连接`。实测端点**完全正常**（`/api/search/status`
返回 200 + `{"enabled":false,"hint":"联网检索已在设置中关闭"}`）——所以问题不在引擎。

**第一层：桌宠窗口的 CSP 漏了 `http://127.0.0.1:*`（真正的 bug）**

```
connect-src 'self' ws://127.0.0.1:*      ← 只放行 WS
```

→ 桌宠窗口里**所有 fetch 都被 CSP 拒绝**（联网状态、模型路径、表演库画廊、
会话列表、**计划批准按钮**），又被各自的 `catch` 静默吞掉 → 表现为"点了没反应 /
引擎未连接"。`dev.html` / `diary.html` 早已放行 http，**唯独主窗口漏了**。

修复：CSP 补 `http://127.0.0.1:*`；同时把 `loadSearchStatus` 的 catch 从
"一律说引擎未连接"改成**如实报出真实错误** —— 误导性归因比没有归因更糟，
它会把排查引向错误方向（这次就是这样：端点好的，却一直在查引擎）。

**★ 判断规则**：**CSP 里 `ws:` 与 `http:` 是两条独立通道** —— 放行了 ws 不代表
http 能用。凡新增 fetch 端点，都要回头确认**目标窗口**的 CSP 是否放行。

**第二层：搜索 key 根本没有配置入口（真缺口 = 有实现、无入口）**

`save_search_key()` 早已实现，但**没有任何 API / UI 暴露它**，`config.toml` 里
连 `[search]` 段都没有 → 用户**无处填 key、也看不见总开关** → 功能等于不可用。

补齐：
| 层 | 改动 |
|---|---|
| 引擎 | `GET/PUT/DELETE /api/providers/search/key`（PUT/DELETE 会**重建 AgentLoop** —— `web_search` 是按"key 是否存在"决定注册的，只存不重建工具依旧不存在） |
| 调试台 | 「能力与安全」页新增 `[search]` 卡片（enabled / provider / top_k + 高级项）；`SectionForm` 的 key 块此前只认 `llm`，现同时支持 `search` |

**★ 判断规则**：**"有实现"不等于"可用"** —— 交付任何需要凭证或开关的功能时，
必须同时交付**配置入口**（API + UI），否则就是"做完了但用不上"。

**验证（第三轮）**：`vue-tsc --noEmit` 0 错；`ruff` 干净；`test_debug_api_panels.py`
+ `test_web_tool.py` 40 passed。

### 4.9 录音设备（麦克风）的检测与切换

用户要求：**所有涉及开启麦克风 / 语音的入口，都要能检测并切换录入设备**。

此前三处采音都是 `getUserMedia({ audio: {...} })` —— **不指定设备**，于是永远只能用
系统默认麦：插了耳机仍从外放麦收音，用户既不能切换、也看不到系统里到底有没有麦。

| 入口 | 文件 |
|---|---|
| 桌宠聊天坞语音（`/ws/audio` 对话链路） | `composables/useVoiceInput.ts` |
| 日记窗口语音（只送 ASR 转写，不进对话链路） | `diary/useRecorder.ts` |
| 调试台「语音联调」 | `dev/components/VoiceDebug.vue` |

补齐：
| 层 | 内容 |
|---|---|
| **内核** | 新增 `composables/useAudioDevices.ts`：枚举 / 选中（localStorage 记忆）/ `devicechange` 监听 / 跨窗口 `BroadcastChannel` 同步 / **`openStream()` 统一开麦** |
| **UI** | 新增 `components/MicDevicePicker.vue`，三处入口都挂上（聊天坞在语音展开区、日记在工具栏、调试台在采音按钮旁） |

**「检测」为什么比看上去难 —— 三个必须处理的现实**：

1. **未授权时 `label` 是空串**（Chromium 隐私策略）：直接 `enumerateDevices()` 只能拿到
   一堆无名设备。要读到"麦克风阵列 (Realtek…)"这种真名，必须**先申请一次麦克风权限**
   再枚举 —— 而申请会点亮系统指示灯，所以探测**只在用户主动打开设备列表时**发生
   （`refresh(true)`），**绝不在页面加载时静默开麦**。未授权时列表明确显示
   "麦克风 1 / 2"，不留空白让人以为坏了。
2. **设备会被拔掉**：选中的 id 不存在时，`deviceId: { exact }` 会直接抛
   `OverconstrainedError` —— 那会让"开麦"**整个失败**。`openStream()` 的策略是
   **自动回退系统默认并告知**（"之前选择的麦克风已断开，已回退到系统默认"），
   而不是把失败丢给用户。
3. **跨窗口**：桌宠 / 日记 / 调试台是三个独立窗口。同一 origin 下 localStorage 共享 →
   选择天然全局生效；再用 `BroadcastChannel` 让改动**立刻**同步（在日记里换了麦，
   聊天坞随即跟上）。

**顺带修掉的**：三处采音原本都把错误笼统报成"无法访问麦克风（请检查系统权限）"——
而"**没插麦 / 被拒权 / 被别的程序占用**"的处理方式完全不同。新增 `describeMicError()`
按 `DOMException.name` 分类给出可操作的话：`NotFoundError` → 请插入一个录音设备；
`NotReadableError` → 关掉占用的会议 / 录音软件；`NotAllowedError` → 去系统设置放行。

**★ 判断规则**：**"能用"不等于"能选"** —— 功能只要依赖某个**外部设备或环境**，
就必须给用户一个**看得见、能改**的入口；否则换了设备、插错了口，用户只会以为"功能坏了"。
另外，**开口（`getUserMedia`）只保留一个**（`openStream`），回退与错误翻译集中在那里；
三处各写一遍，迟早有一处漏掉兜底。

**验证（第四轮）**：`vue-tsc --noEmit` 0 错；`electron-vite build` 通过。

### 4.10 调试台「日记」页：封面化 + 纸感扩散（附一条代价最大的教训）

用户要求这一页"整体脱离调试台的设置编排，做成一本本子的封面"。落地：
`page-diary` 专属容器（不限宽、去掉通用入场）+ 皮革烫金封面（字号用 **`cqw` 按封面
宽度缩放**，四字书名恒定一行）+ 翻开 / 合上 3D 掀开 + 内页「纸感扩散」。

**★ 判断规则（本轮代价最大的一条）**：
**"改了没效果"要先怀疑"动画是否真的在运行"，再怀疑参数。**

「渐显」连调四轮都毫无变化，最后发现根因是 `prefers-reduced-motion: reduce`
（系统开了"减少动态效果"）—— 我此前在这个媒体查询里一刀切写了 `animation: none`，
于是**所有 CSS 动画在这台机器上从未播出过**。修法：

- 该偏好要防的是**运动**（位移 / 缩放 / 旋转 / 视差）；纯**透明度渐变**是无害且必要的
  层次提示 → **保留淡入，只去掉位移**；
- 关键效果改用 **WAAPI（`element.animate()`）** 驱动 —— 它**不受该媒体查询影响**，
  并在偏好为 reduce 时**缩短时长**而非取消；
- 用 **mask 的径向羽化**（而不是 `clip-path` 的硬边）做扩散，边缘才是"墨 / 光晕"的样子；
- 初始 mask **不写进 CSS**：万一 JS 没跑，内容至少还能读 ——
  **效果可以没有，可读性不能赌**。

同样值得记的还有两条 CSS 排查经验：
- **"某处发暗"先怀疑背景渐变**：`linear-gradient(180deg, ...)` 会随元素高度整体压暗，
  比投影更隐蔽（投影溢出到元素外，渐变就在元素**里面**，看着像"它本来就是这个颜色"）；
  本轮"底部渐变黑影"是**书壳 + 纸页 + 纸页投影**三层叠加，前两轮只改投影自然无效。
- **交互态优先级会盖掉状态修饰**：`.cover:hover`(0,2,0) 高于 `.cover-leave-to`(0,1,0)，
  于是"悬停着点击"时掀开的 `rotateY` 被 hover 盖掉 —— 表现是"合上有动画、翻开没有"。

### 4.9 联网检索**独立成页** + 引擎侧状态卡（用户实测反馈）

用户把总开关拨到"开"，却仍收到「联网检索已在设置中关闭」——截图里卡片右上角是
**「未保存」**：那个开关只改了**草稿**，没提交到引擎，引擎侧 `enabled` 仍是 `false`。

这暴露一个**普遍的界面陷阱**：配置卡显示的是**草稿**，而桌宠/聊天坞判断的是
**引擎实际状态** —— 两者不一致时，用户会认为"我明明开了，怎么还说没开"。

改动：
| 项 | 内容 |
|---|---|
| 导航 | 「联网」**独立成 tab**（「调教」组、「日记」之后），从「能力与安全」移出 |
| 页面 | `TAB_SECTIONS.search = ['search']` → 总开关 / 后端 / 条数 / 超时 / 接口地址 + 搜索服务 Key 输入 |
| ★ 新增 | **引擎侧状态卡**（`SearchStatus.vue`，置于配置卡**之上**）：直接显示引擎的真实值 —— 总开关是否真的为 true、`web_search` 是否已注入模型、不可用的**人话原因**；并明确点出"这里显示已关闭而开关是打开的 = 还没保存" |

**★ 判断规则**：**配置界面必须区分"我想设成什么"（草稿）与"现在实际是什么"（生效值）**。
只显示草稿，用户就无法判断"是我没保存，还是它坏了"。凡有保存动作的配置页，
都应把**引擎侧生效值**摆在旁边（至少对"影响功能可用性"的关键开关如此）。

### 4.10 "开了联网却还是没搜"：**两个开关 + 零提示**

现象：用户在调试台开启总开关后问"今天河北的天气如何"，回复"我又不是气象站"；
日志特征 **`轮数=1/3`**（没有任何工具调用轮）。

三项并行取证：
1. `/api/search/status` → `enabled:true, available:true`；`/api/providers/search/key` → `set`
   —— **引擎侧完全正常**；
2. 日志有 `配置已更新并热重载: ['search']` + `搜索 key 已更新并重建 AgentLoop` —— 装配成功；
3. 前端 `send()` 每轮都带 `web_search: webSearchOn.value`，而 `webSearchOn` **默认 false**
   （localStorage 无值）→ 引擎把 `web_search` 从工具表**过滤掉** → 模型看不到它。

**根因**：联网检索有**两个开关**（调试台总开关 + 聊天坞地球按钮），后者默认关，
且**没有任何提示**。用户"我开启了联网功能"的心智模型与实现不符，陷入死循环。

| 项 | 修复 |
|---|---|
| 前端 | 地球按钮默认值改为**跟随引擎总开关**（从未显式选过 → 引擎可用即默认开；显式点过则尊重其选择并记住） |
| 引擎观测 | 工具表可见性**留痕**：本轮禁用了哪些工具、`web_search` 是否已注入 —— 此前被静默过滤，日志里毫无痕迹，只能靠猜 |

**★ 判断规则**：**同一功能的开关只能有一个"权威源"**。若因场景需要保留第二个
（如会话级临时关闭），它必须**默认继承权威源的状态**，不一致时给出提示 ——
否则用户必然掉进"我明明开了"的坑。

### 4.12 日记回顾页「Not Found」：**漏了 `/api` 前缀**

现象：日记已落库（`日记已落库 id=2`），调试台「日记」页却整页 `Not Found`；

根因：`diaryApi` 的路径写成 `/diary/list`，而引擎 router 的前缀是 `/api`

| 美化 | 整页重做成**日记本形态**（见 §4.13） |

### 4.13 日记本形态 + 语音"边说边出字"

用户要求：① 回顾页做成**日记本形式**（游戏质感），不要列表 + 筛选；② 语音识别的文字
应**实时流进键入区**，且**不该需要点两次麦克风**；③ **不要自动收麦**（会打断写日记时的思考）。

**回顾页 → 书**：
- 深色调试台里的**暖纸书**：纸质渐变 + 横格线 + 装订线 + 页角折痕，正文衬线字、行高贴合格线
- **两个视图**：目录（书的索引：页码 + 日期 + 摘句 + 档位贴纸）/ 阅读（一页一天）
- **翻页**：按钮 + 键盘 `← →`（`Esc` 回目录）+ 3D 翻页过渡；当前页在目录里留一条书签
- 隐私档做成**页角贴纸**；删除做成「撕掉这一页」（仍需二次确认 —— 会连带删记忆）

**语音 → 输入法式**（前端静音分句，引擎未改）：
| 项 | 做法 |
|---|---|
| 出字时机 | 本地句末检测（自适应底噪 + 尾静音 900ms）→ 每句送 `/api/diary/transcribe` |
| 文字去处 | **追加到输入框**（可继续编辑），不再直接成段 |
| 顺序 | 识别任务**串行化**（promise 链）—— 并发返回会乱序，串起来才保证按说的顺序出现 |
| 收麦 | **永不自动停**（`autoStopMs` 默认 0），想停手动点一下 |
| 噪音防护 | 要求"有效人声帧 ≥3"才送识别（比只看时长准：噪音里超阈值的帧很少） |

**为什么不做真正的逐字流式**：引擎的 SenseVoice 是**整段**模型；真流式要换模型或做增量
重识别（重复计算 + 中文尾部反复改写会让字在屏幕上抖）。按静音切句分片，手感已是
"说一句、出一句"，代价小得多。**把"流式体验"与"流式实现"分开** —— 用户要的是没等待感。

**★ 判断规则**：**涉及"要不要替用户结束"的自动化，默认应该关**。停顿在不同场景语义
完全不同（聊天里 = 说完了；写日记 = 在想）。自动结束一旦误判，用户丢掉的是
"还没说完的话" —— 代价远大于省下的那一次点击。

### 4.14 语音噪音防护（聊天链路 + 日记链路**共用同一判定**）

用户要求：日记侧的噪音防护，聊天语音同样重要，补进去。

**先核实（不盲目加）**：引擎侧其实**已有三道** —— VAD 神经网络判"有没有人说话"、
ASR 空文本跳过、SenseVoice 情感标签剥离（`<|NEUTRAL|>`）。

**但确实缺两道**：
| 缺口 | 后果 |
|---|---|
| 极短音频（VAD 被一声响动误触发） | 0.1s 也照送 ASR → 白跑一次 GPU 推理（~100-300ms） |
| **非空但无意义的转写**（`"嗯。"` / `"(咳嗽)"` / `"[Music]"`） | **不是空**，于是一路走进 LLM → 用户看到"她突然回应了一声响动" |

**补齐**：`audio.is_noise_transcript()`（纯函数）+ 极短音频下限，**聊天语音链路与
日记转写端点共用同一判定**（不再各写一份）。

判定规则（**保守**）：纯标点 / 纯括号描述 / 仅填充词**且 ≤6 字符** → 噪音；
像一句话的一律放行 —— "嗯，我知道了""下一首""停" 都必须活下来。

**★ 判断规则**：语音入口的过滤必须**分两层**：
① **音频层**（太短、不像人说话）；② **文本层**（识别出来了但没内容）。
只做一层必有漏 —— 只查空文本会放过 `"嗯。"`；只看时长会放过"一整段背景音乐被转成歌词"。
