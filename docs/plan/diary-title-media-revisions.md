# 日记标题、多媒体附件与修订（2026-10-29）

## 目标与实现

保存原文已并入语音输入的同一操作栏，移除底部“关闭”文字按钮；窄窗口按剩余宽度自然换行，不压缩可操作区域。主编辑器增加可留空的标题，未命名旧记录仍以摘要回退显示。标题独立保存并参与搜索，不把标题强行混入正文。

新增附件区，支持选文件和拖入：PNG/JPEG/GIF/WebP、WAV/MP3/OGG、MP4/WebM。图片就地预览，音视频原生控件播放，均可下载；编辑时可移除。每篇最多8个附件，单文件20MB。标题或附件单独存在也可保存，无需凑正文。

“所有记录→打开记录→编辑记录”可修改标题、正文及附件。保存前校验版本号，有其他窗口修改时拒绝覆盖，并保留本地编辑。修订历史可将旧标题、正文及附件载入编辑器，再保存成新修订；恢复不会抹掉中间版本。

参考 [Day One 的多媒体记录能力](https://dayoneapp.com/features/)组织文字和图片/音视频，参考 [Obsidian 的完整快照恢复](https://obsidian.md/help/plugins/file-recovery)保留修订。这里采用显式保存时快照与版本校验，未照搬定时快照或引入富文本编辑器框架。

## 存储与记忆边界

- `diaries` 增量增加 `title`、`revision`，旧数据库自动升级，不重建、不批量改写旧正文。
- `diary_assets` 存在当前角色日记库中，二进制不写聊天上下文或记忆。上传按签名字节识别类型，不接受客户端磁盘路径；读取用鉴权请求转Blob URL。预览卸载时释放URL。
- `diary_revisions` 保存旧版本完整文字快照及附件ID；二进制不随每个修订复制。移除的附件在历史中保留，删除整篇日记时通过外键连带删除附件与修订。
- 未保存的附件属于暂存，超过24小时后在下一次上传时清理；暂存总量上限160MB。不是定时后台清理，也不是草稿磁盘自动恢复。
- 新增上传/媒体读取/修订/编辑接口校验本地密钥与角色；角色切换期间的旧上传不能写入新角色库。
- 编辑后清除旧润色稿、摘要衍生标签和旧总评，原文成为新的阅读正文，避免显示与新内容不符的旧结论。
- 已共享日记先撤回旧记忆，再更新正文并按原隐私档位写新记忆。撤回失败时不修改正文；新记忆写入失败时正文仍保存，前端明确提示。附件本体不发送LLM，当前多模态范围是插入、存储、预览与播放，不包含自动识图/转写。

## 2026-10-29：开发环境401修复

用户实测附件POST、编辑PUT返回401，阅读GET正常。代码排查发现新媒体guard对开发占位密钥强制比较，而既有WS和角色接口将空值/`dev-only-change-me`视为开发模式。壳若未继承env.ps1，getEngineSecret返回空值，造成新增功能独有401。

已统一guard与既有行为：仅配置真实密钥时严格比较；真实密钥错误仍返回401并给出环境不一致提示。角色归属检查仍返回409，不因修复401而放开跨角色访问。

回归将完整上传→读取附件→编辑→版本冲突→历史→恢复流程参数化，覆盖真实密钥、开发占位且壳为空、两端为空；另外验证真实密钥缺失/错误时上传和编辑仍拒绝。相关13项通过。修复需重启引擎加载，无需改变角色声音或重建数据库。未修改用户真实记录；本轮验证为临时库接口集成测试，未冒充桌面实测。
