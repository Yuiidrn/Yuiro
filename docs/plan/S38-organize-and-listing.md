## 1. 验收实录（真实 LLM + 真实目录）

**目标目录**：`D:\Project\Yuii\desktop-pet\test` —— 29 个文件 / 8.7 MB
（12 pdf · 9 docx · 4 xlsx · 2 png · 1 xls · 1 txt + 3 个既有子目录）

**工具**：`engine/scripts/accept_organize.py`（可复跑；`--execute` 才真的动文件）

| 轮次 | 结果 | 暴露的问题 |

| 第 1 次（只读） | 第 2 轮就卡死："工具返回了完成状态但没给我具体文件列表" | ① 工具结果**二次 JSON 转义**（长度翻倍、需解两层）② 工具结果**不进下一轮上下文** → 重复调用同一个工具 |

## 2. 四个修复

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| **①** | **没有"列目录"能力** | 只有 `file_read`（读单文件）—— "整理文件夹"连第一步"看清有什么"都做不到 | 新增 **`file_list`**：目录 + 子目录 + 每文件（扩展名/大小/修改时间），**按大小降序**（大件优先看到），支持 `pattern` / `recursive`；`LOW` 风险、免审批 |
| **②** | **工具结果二次 JSON 转义** | `SystemActionTool._invoke` 把已是 JSON 的 `stdout` 再 `json.dumps` 一层 → `{"stdout": "{\"count\":3…}"}`：长度翻倍（近半是 `\"`）、更易撞截断阈值、模型要解两层 | `_invoke` **解包结构化结果**（dict → 扁平化；list → `items`；纯文本才走 `stdout`）。**一处修复，全部系统工具受益** |
| **③** | **工具结果不进下一轮上下文** | 每轮 `_build_messages()` **重建** messages（只有状态摘要，没有结果内容）→ 模型看不到内容 → 重复调用同一个工具 → 被去重挡回 → 彻底卡死 | 新增 `round_tool_results`（本轮结果，≤3 条 × 2000 字符）注入下一轮 system 段："**直接基于它继续，不要重复调用同一个工具**" |
| **④** | **长任务半途而废** | 模型（qwen）倾向"用文本表达计划"（"现在把剩下的也分一下"）然后停 | **写操作后续跑**：一旦本轮对话发生过写操作，之后每次"只产出文本没有动作"就推一把（上限 3 次）。判据用**事实**（发生过写操作）而非关键词 —— 实测关键词在打地鼠（"剩下的图片"→"剩下5个docx"→"先看看那两个文件"三次都漏） |
| **⑤** | **`file_move` 把"移到新目录"当成"重命名"** | `_plan_moves` 只认"多文件 / 已存在目录 / 尾部分隔符" → 单文件 + 无扩展名 dest 被当成重命名 | dest **无扩展名即视为目录**（`D:\x\图片` 显然是想进/建目录）。**这个 bug 直接导致 `.xls` 变成叫「表格文件」的无扩展名文件，模型随后彻底困惑** |

> ⑤ 是本次最有价值的发现：**看起来是"模型犯傻"，实际是引擎语义太窄**。
> 报告里的"模型把计划当行动"，有一半是它被错误的世界状态带偏了。

## 5. 遗留（诚实清单）

| 项 | 说明 | 建议 |
|---|---|---|
| **`file_roots = ["."]`** | 默认只能碰 engine 目录 —— 本次验收是**脚本内临时放开**才跑通的。你要在桌宠里用，**先改 `config.toml`** | 见 `Agent-test-matrix.md` §0 |
| 长任务收敛仍靠"推" | 写操作后续跑是**启发式**（事实信号 + 上限）。真正的解是 **TaskRuntime 驱动**（任务 RUNNING 时按步执行） | S39 候选 |
| 无"整理预览" | 目前是"扫描 → 直接移动"。理想是"**先给预览**（哪些文件移到哪），用户确认后再动手" | 复用 S29 的 `task_plan` |
| 分类粒度 | 「PDF文档」里混入了 docx（模型按"文档类"归类）——**不是 bug**，但它说明提示词可引导更细的分类 | 可选 |
| `file_list` 无分页 | 目录超 80 个文件只回前 80（`truncated: true`） | 按需加 `offset` |
