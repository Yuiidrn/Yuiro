# 极简单曲线对白与客户端原生搜歌（2026-10-26）

## 目标与边界

Goal：增加“文字 + 单条开放曲线”的对白表现，保留原气泡；让单曲搜索、ID 读取、选择和播放脱离本项目的 ncm-cli/网易云开放平台取数链路。Scenario：两角色均可自然语言搜歌或直接搜歌，结果卡来自官方客户端，选择原版后在官方客户端播放/暂停；切换角色清理旧内容。

Architecture Increment：沿用 Runtime/Session/Generation/角色 quiesce、NativeBackend 与现有结果卡，仅增加一个不可交互的曲线呈现层、客户端 UI 搜索适配器和明确的搜索消息。没有引入新框架、改角色人设/音色，或恢复旧播放器作为隐式回退。

DoD：两角色真实资源显示正确；曲线无背景/箭头/闭合路径且始终点击穿透；样式热更新与模式切换正确；客户端查询词与 ID 可核验；原版 ID 播放/暂停、旧身份拒收与取消、回归测试及文档有证据。

## 已实现

### 单曲线对白

- 调试台 **UI → 独立回复与结果面板 → 回复气泡 → 对白表现**，可切换“气泡”和“极简单曲线 · 无背景文字”。深色/浅色桌面各有预设，旧漫画气泡预设保留。
- 单曲线模式正文无底色、描边或封闭框，代码/引用等 Markdown 子元素也不再加背景框。每条当前回复只连接一条平滑开放三次贝塞尔曲线，无箭头/三角尖端/额外端点装饰。
- 字形（系统、宋体、楷体、等宽）、字重、字号、字间距、行距、段间距、对齐、文字色、阴影色/强度、线色/粗细均可热更新；支持在调试台直接预览真实模型与文字的关系。
- 对 Hiyori、Hotaru 当前全身资源提供不同的静态嘴部侧点标定，随资源路径选择；可关闭标定改为手动比例锚点。**不是自动识别、逐帧嘴部追踪**，模型换资源或大幅改变姿态后应重新标定。
- 文字沿用已有独立轻量窗口和避让；曲线另用透明、不可聚焦、全窗口点击穿透的呈现窗口，允许从模型嘴部附近连到文字，不把一整块覆盖模型的透明文字窗口做成可点击区域。切换、隐藏、最小化及内容清理一并隐藏曲线。曲线包围区参与后续卡片避让。

### 客户端原生单曲搜索

1. 核验回环端口、官方 exe 所属 PID 和固定主页面；找到可见的客户端全局 `.searchbox` 输入框，通过原生键盘输入触发搜索。
2. 从客户端搜索页面的公开 DOM 元数据读取当前查询词，并只提取单曲卡片的数字 ID、标题和歌手；不读取账号、Cookie、访问令牌、完整 store 或日志跟踪参数。
3. 查询词必须与请求一致，候选在连续两次快照中稳定后返回。目前限定综合搜索页面**可见的最多 6 首单曲**，不把播客/声音卡片当成歌曲。原版和 Remix 保留原来的 ID/名称，不按可播标志重排或替换。
4. 结果卡显示“客户端搜索：查询词”和“来自网易云客户端内搜索”；播放继续使用原有官方客户端 ID/状态双重回读与角色归属。
5. 日常 `netease_search` 注册替换为 `NeteaseClientSearchTool`，无 ncm-cli 环境门槛；旧 API 工具源码保留。普通聊天/语音不开放旧 API 登录、搜索替代、歌单、歌词、自动推荐或账号写入工具。客户端不兼容、未连接、查询不匹配或超时均明确失败，**不回退 ncm-cli/旧 API/mpv**。
6. 新增不依赖 LLM 的正式入口：输入 **`/搜歌 Monody`**（或 `/music Monody`），也可将歌名填进聊天框后，在输入框菜单选择“搜歌（不经大脑）”。这是明确的 UI 命令，走认证 WS 与相同角色/会话边界，不是诊断时伪造结果卡。

“不使用 API”指 **Yuiro 的音乐适配不直接请求网易云开放平台/私有 HTTP 搜索接口**；官方客户端本身仍正常联网。当前只替换单曲搜索与播放，不宣称完整歌单/歌词/推荐/收藏能力都已替换。

客户端未运行时，显式搜索可启动本机连接；已经运行但没有可核验连接时，不强制杀进程/重启，提示退出客户端后重试。冷启动搜索分支有单测，本轮实机主要验已连接客户端。

### 已解除的 LLM 阻碍

首轮 Hiyori 使用 `qwen3.8-flash` 时返回 403 `insufficient_quota`，消息指向 free tier exhausted；同一安全密钥的 Hotaru `qwen3.8-max` 最小请求返回 200。[原始诊断摘要](line-client-artifacts/quota-diagnostic.json)、[中止记录](line-client-artifacts/agent-blocked.json) 保留，不作为最终失败。

用户随后将 Hiyori 改为 `qwen3.8-max`，本轮自然语言全链路两角色已通过。没有更换用户密钥、充值或关闭“免费额度用完即停”。[阿里云额度说明](https://help.aliyun.com/zh/model-studio/new-free-quota/)指出每个模型/快照独立计算免费额度，因此不能将这次 Flash 403 解读为整个账户没余额。

## 随机推荐和喜欢：调查结论

- **当前候选随机选择**：已有按钮继续可用，现在候选来自客户端内搜索；它是从当前可见 ID 中随机选歌，不冒充平台个性化推荐。
- **客户端随机播放模式**：读到了 `aria-label=shuffle`、标题“随机播放”的控件，存在隐藏/可见两份视图。尚未验证模式切换与回读，不把标题直接当作可调用协议，也不操作全局媒体键。
- **加入喜欢**：能按 Monody 的结果卡 ID 定位到 `btn_pc_like` 按钮，播放栏也有“喜欢（Ctrl + L）”；但 `aria-pressed` 未提供状态，播放栏还存在隐藏副本。只找到按钮不等于收藏成功。当前没有写账户、改变红心或试点快捷键。只读证据见 [client-capabilities.json](line-client-artifacts/client-capabilities.json)。
- 网易 [公开 Skills](https://github.com/NetEase/skills)的推荐仍依赖 CLI，不能拿它证明客户端原生私人 FM/喜欢桥接已完成。本轮只接入实际验证稳定的单曲搜索和 ID 读取。

后续接入喜欢时：用户明确发起操作 → 核对当前/目标 ID → 读取现态 → 按目标状态操作一次 → 重新读回 ID 和喜欢状态。未知结果不得重复 toggle；角色切换、手动换曲、隐藏副本或未验证状态都拒绝执行。平台推荐需另外验证推荐页/队列来源与 ID，不将“随机候选”改名冒充私人 FM。

## 限制与下一步

当前搜索是已验证客户端 DOM 的窄适配，非公开稳定 SDK。UI 结构变化即失败，未做多版本兼容；不支持分页全部结果、歌单/专辑检索与可靠“零结果”识别（无法核验时超时提示）。嘴部标定为当前两份资源的静态比例，未做动作驱动嘴部语义追踪、多屏混合 DPI 或连续拖动帧时延基准。

下一步优先补：不同查询/零结果/分页与版本体检 → 喜欢现态及写后回读 → 平台推荐页来源验证；演出侧再独立验证动态锚点与多屏重排。继续局部迁移，不推进 G1。
