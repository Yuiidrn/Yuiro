# 双角色漫画UI与自然语言音乐验收

日期：2026-10-26。延续现有Runtime与客户端适配，小范围完善表现和语义指代。

## 五要素

- Goal：对白框自然圆润；Hiyori/Hotaru两套一致而简洁的视觉；自然语言即可收藏当前角色拥有的歌曲。
- Scenario：“推荐几首歌”“喜欢这首”“取消喜欢”，正常对话不指定工具名或数字ID；自动换肤、滚动长文与切换清理。
- Architecture Increment：表现层增加皮肤tokens/连续SVG轮廓；收藏工具允许省略歌曲ID，仍由引擎现有播放归属核验。不新增Runtime或音乐后端。
- Tests：双角色真实UI/自然语言Agent/网易云客户端；几何、主题、指代与归属单测及既有回归。
- DoD：不臆测歌曲，不控制另一个角色/播放器，不静默回退；收藏读回同步到卡片，最后恢复原收藏状态；样式规范与实测证据落盘。

## 已完成

### 漫画对白与主题

按用户两张参考图重绘框体/尖尾的一体闭合轮廓：柔白双描边、漫画墨线两种笔触。保留无背景单曲线模式。角落原创星光/白花可关闭；长回复滚动、自动避让和Markdown安全规则继续使用已有实现。

“角色 UI 风格”支持自动、奶油星光、百合与茉莉。自动随角色同步调试台、独立对白、结果/来源卡、输入栏和功能岛；支持日/夜和手动固定。默认不覆写既有字号、偏移或对白表现模式，需要完整漫画预设时在UI页点击“试用漫画曲线预设”。

样式来源、颜色矩阵、装饰/交互约束、实现位置及实际截图见 [样式参考规范](../UI&motions/character-ui-style-reference.md)。

### 自然语言指代修正

旧收藏schema强制song_id，模型面对“喜欢这首”只能依赖对话里的候选ID，易混淆。现`netease_favorite`只强制liked；省略ID时由`favorite_owned`取**当前角色有效归属的精确ID**，随后仍读回客户端当前ID核验，不是取任意SMTC歌曲或首个搜索候选。

无归属、另一角色、人工切歌仍拒绝。显式传错ID不被默认覆盖。Agent只有客户端目标状态读回成功才可报告成功；卡片复用既有5秒状态轮询同步，不更改所有权和取消语义。

## 自然语言真实验收

脚本：`scripts/diag/natural_music_acceptance.py`。用户话术未含工具名或数字ID。自然搜索“TheFatRat和Laura Brehm的Monody原版”后，由测试从真实候选中点选36308916，随后按实际操作验证：

| 项目 | Hiyori | Hotaru |
|---|---|---|
| 自然搜索、点选原版、播放/暂停 | 通过 | 通过 |
| “喜欢这首”→平台读回且卡片更新 | 7.84秒 | 7.38秒 |
| “取消喜欢”→平台读回 | 9.08秒 | 8.62秒 |
| 取消后卡片恢复未喜欢 | 通过 | 通过 |
| “推荐几首歌”→客户端日推 | 6首真实候选 | 6首真实候选 |
| 推荐不改变当前歌曲ID | 通过 | 通过 |
| 初始/最终喜欢状态 | false→false | false→false |

延迟是本机单轮端到端观测，包含模型决策/客户端回写/轮询，不是SLA。平台收藏为账号共享；角色隔离保护操作权限及结果，不建立两份账号收藏。

最终切换后旧结果卡和播放归属清空，恢复Hiyori；原版Monody收藏恢复未喜欢。不会自动恢复此前客户端页面位置或未归属用户歌曲的播放进度。

## UI验收

- 两角色×柔白/墨线，实际SVG只有一条闭合几何轮廓（双描边可重复描同一路径）；无拼接尾巴。
- 角色自动风格、手动固定与恢复自动、白花夜间配色、输入栏token同步通过。
- 长文滚动、装饰关闭、安全Markdown、宽回复不遮模型、模型相对预览不缩放真实宠物、功能岛尺寸热更新通过。
- 无背景单曲线的透明文字/开放路径/点击穿透、参数热更新和切换清理回归通过。
- 仅测试本地展示文字与真实角色资产；UI预览没有调用大脑、音乐或外部图像服务。
