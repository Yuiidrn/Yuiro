# 角色演出工作台与 Agent 表演稳健性

日期：2026-11-01。当前增量已交付；持续 Live2D 自然度主线仍见 [实施记录](live2d-expression-evolution.md)。

## 目标与边界

- Goal：从文字列表升级到可以看模型、试动作、看表情、管理互动的工作台。
- Scenario：先选择模型缩略图，在左侧舞台试播右侧资源，再决定是否应用到当前角色；动作可加入该角色、该模型的单击池。
- Architecture Increment：复用 Live2DCanvas、Manifest、PerformanceEditor、AvatarRuntime 和现有角色配置；新增资源目录视图、单舞台预览与 Agent 同表演合并。
- Tests：壳层类型检查/构建、前端行为回归、Python 全量回归、真实 Electron 构建页的两模型与资源交互。
- DoD：普通预览不改配置、不广播到桌宠；真实资源可试播、分类和收藏；切模型取消过期缩略图任务；保留原有配置编辑能力和优先级/代际契约。

## 已交付

1. 外观页改为左右工作台：模型图卡、单个实时 Live2D 舞台、动作/表情/Agent 演出/单击反馈/互动节奏/资源维护六区。继承当前角色的奶油与白花主题变量。
2. 模型来自真实扫描，合并注册表名称、作者与隐藏标记；已隐藏的形象不再因为目录仍存在而重新露出。预览另一模型不会切换角色或覆盖其配置，应用仍需明确点击。
3. 资源按招呼回应、愉快庆祝、思考关注、陪伴含蓄、情绪变化、日常待机及待分类收纳。搜索、每页12项、角色+模型独立收藏，保留原文件名、组/索引和时长供核对。
4. 点击卡片在舞台播放，并生成实际模型截图；“生成本页预览图”复用同一个舞台串行采样，不创建十二个模型渲染器。表情截图取头部区域。初始模型图来自本项目实际画布。
5. 默认只在调试台预览；明确勾选“同时在桌宠上试演”后，才经既有带 characterId/modelPath 的 IPC 发送。非当前模型禁止此选项，缩略图批处理也不发送桌宠试演。
6. 可直接将具有动作的资源加入单击反馈池，自动去重；纯表情的 Agent 演出不显示无效的加池按钮。原有推荐/移除/清空和互动节奏参数继续保留。
7. 模型/角色变化及离页使异步目录、缩略图结果失效；加载失败退出等待并禁用应用。Agent 搭配编辑器的试演改接左侧舞台，保存和热重载仍走既有接口。
8. AvatarRuntime 合并同一未结束 Agent 表演的重复请求，避免反复起播；映射实质改变时允许更新，播放结束或过期后可再次播放。工具说明明确 skipped 应继续对话、不刷重试；成功发送不等于动画完成。

## 真实限制与下一步

- 缩略图是开始试播约450ms后的静态采样，不是GIF，也不代表整段动作均已视觉审定；长动作以左侧实时舞台为准。点击或批量生成后才有对应资源截图，未采样项目保留播放入口。
- 分类基于已有语义槽位，未知资源明确待分类，不把文件名猜测当作人工审定。下一步应结合逐动作观看补充角色专属安全/情绪标注。
- 本轮不自动将更多动作混入常驻待机，不增加第二套 Agent/Avatar 调度；用户之前反馈的注视与待机自然度仍须持续确认，不能用本轮目录和绿色测试代替。
- 本轮实机验证的是本地工作台与配置隔离；新的重复合并由自动化覆盖，未额外消耗云端LLM进行自然话术长测。
