# 三面板并存与双角色桌面 UI 验收（2026-10-26）

## 目标和改动边界

场景：长回复、歌曲候选、联网来源同时出现，模型仍可点击和拖动；贴近屏幕边缘时，各面板留在工作区内且不压住模型；调试台调整立即生效。仅改呈现状态、轻量窗口路由和布局算法，继续复用当前 Runtime、引擎连接、轮廓命中、渐隐和播放器归属。

完成条件：两个实际 Live2D 角色各检查居中、四角、拖动前后及热更新后八种位置；各窗口与可见模型矩形、彼此均不相交；长文字可滚动；来源独立收起；角色切换清空全部旧内容；恢复测试前的偏好、角色、模型布局和鼠标位置。

## 发现与局部修复

1. 原先歌曲和来源共用 `resultCard`，后到的结果覆盖先前内容。新增独立 `sourceCard`、来源计时器和按需创建的来源窗口；回复、歌曲、来源可同时显示。新文字/ASR 回合仍清旧来源，切角色清三类内容。单独关闭来源不清歌曲，歌曲关闭也不清来源。
2. 原布局主要考虑两个面板，第三张卡可能在还有空位时被隐藏。保留首选左右/上下位置，再搜索模型和已有面板边界及工作区角落；额外候选优先选择靠近角色的位置，避免无必要地跳到屏幕另一端。
3. 来源窗口只允许来源点击和收起；主进程继续核对发送窗口、角色快照 key 和索引，不允许来源窗口发送歌曲播放/暂停等命令。歌曲 ID 和播放器控制链保持原样。
4. 调试台补充三面板可并存的说明，继续使用现有回复、音乐、来源的独立外观设置，无需新增配置页。

## 实测证据及口径

运行环境：当前 Windows 桌面工作区 1920×1080 物理像素，有 DPI 缩放。通过真实 Electron/Vue 窗口和 Engine 角色切换测试；歌曲和来源由实际 Agent 检索取得，不替换服务商、不伪造检索回包。选歌场景仅检索/展示候选，不启动音乐。本轮不重复上轮的音乐听感与播放权益验收。

- [live.json](ui-multi-artifacts/live.json)：最终布局代码下的 Hiyori 结果与 Hotaru 长文请求不足导致的中止记录。Hiyori 实际长回复 1,096 字，5 条歌曲、3 条来源，八种几何检查及原生拖动通过；字号热更新观察值 3 ms。Hotaru 在这次请求中仅总结“长文已完整输出”，未给正文，不能将该请求标为长回复成功。
- [hotaru-stress.json](ui-multi-artifacts/hotaru-stress.json)：Hotaru 单独补验，真实查询结果配合长文字显示检查。若原回复不足 600 字，脚本明确标注“排版压力样本”，用同角色真实回复/检索摘要重复展开；这是 UI 压力测试，不冒充新的 LLM 长回复。以回执中的 `long_reply_mode` 为准。

Hotaru 补验已通过：真实原回复 84 字、5 条歌曲、3 条来源；显式展开的压力样本 8,953 字，滚动高度 32,203 px、可视高度 320 px。八种布局均无模型/面板重叠，原生拖动模型移动约 62×20 物理像素，字号更新观察值 2 ms，来源独立收起、角色切换清理、偏好还原均通过。这些毫秒值只是观察值，不作为端到端响应或连续拖动性能保证。

- 原生鼠标点击来源窗口的“×”，只收起来源；回复与选歌候选保留。通过实际数值输入控件调整回复字号，跨窗即时更新；来源独立宽度/字号/摘要行数和各面板最大高度热更新后再次检查避让。
- 拖动使用当前角色 Alpha 遮罩内的不透明点，实际发送 Windows 鼠标按下/移动/松开；记录模型和各面板的物理坐标，不用 CSS 假移动代替。
- 实际截图检查了回复滚动区、歌曲版本及播放器按钮、来源标题/摘要/日期。截图仅保留在本机临时目录，报告不包含桌面其他应用或账户信息。

回执中的 `preferences_restored` 表示对应测试的显示偏好已恢复；双角色完成后按 `role_switch_cleanup` 核对切换清理。一次完整预备轮中两角色也完成了真实长回复及八种布局检查，随后仍继续修正候选空位优先级；不将预备轮当成最终代码的替代证据。

## 自动检查与复现

从根目录加载 `config/env.ps1`，保持 Engine 8200 和壳 CDP 9222 在线、普通桌面未锁定。执行期间不要同时操作鼠标或调试台。

```powershell
& .env-local/engine-venv2/Scripts/python.exe scripts/diag/ui_multi_live.py
# 模型不能稳定给长文时，显式 UI 压力补验（回执单列）
& .env-local/engine-venv2/Scripts/python.exe scripts/diag/ui_multi_live.py --role hotaru --stress-long
node scripts/diag/detached_frontend_test.cjs
node scripts/diag/ui_appearance_test.cjs
node scripts/diag/contour_frontend_test.cjs
node scripts/diag/c0_frontend_test.cjs
# shell 目录：pnpm typecheck、pnpm build
```

自动检查覆盖三窗不相交、旧 key/错误窗口/索引拒收、来源不能控制播放器、独立来源计时器、显示偏好归一化和轮廓/角色旧结果回归。本轮未改 Python 引擎实现，不重复无关的后端全量测试。

最终 `typecheck`、生产构建、上述四个 Node 检查及 `ui_customization_acceptance.py` 全部通过；后者额外复测偏好持久化、设置页卸载后同步、主题、分组重置和双角色切换。收尾状态见 [final.json](ui-multi-artifacts/final.json)：Hiyori 在线且模型就绪，三个测试面板全部清空并隐藏；显示偏好已恢复，临时开启的联网意图也已还原。

## 限制

屏幕边缘附近会自动换侧或重排，面板位移不必与模型逐像素一致。当前是保守保护可见模型矩形，轮廓空洞也不放卡，优先保证不遮挡。极小屏幕或字号/卡片尺寸过大时仍可能无合法空位，此时收起对应面板，绝不退回覆盖模型。未实测第二块显示器、不同 DPI 显示器间拖动或系统缩放动态切换；负坐标和工作区边界有纯函数回归，但不等同于多屏实机验收。

模型能否稳定生成指定长度的文章属于独立的 Agent 行为问题，本轮保留真实失败记录，不通过放大字符或伪造后端输出来宣称解决。
