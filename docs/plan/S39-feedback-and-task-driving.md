## 1. F4：任务驱动 v2（从"猜"到"看状态"）

### 之前（S38）的问题

写操作后续跑是**启发式**："一旦本轮发生过写操作，产出文本就推一把"。
它能在"整理文件夹"里救场，但**不知道任务做到哪了** —— 推不出信息，也停不下来。

### 现在（S39）

判据换成**任务状态**（事实）：

```python
_task_line = self._task_progress_line(session_id)     # "0/2｜扫描文件"
_touched_task = 模型刚调过 task_create/advance/retry
if task_nudges < 3 and (_touched_task or (_task_line and _task_line != last_task_line)):
    → 注入「（任务续跑）当前进度：{_task_line}。请立刻动手执行当前步骤…」
```

两个关键点：

| 点 | 为什么 |
|---|---|
| 注入**带进度**（`0/2｜扫描文件`） | 模型知道"做到哪、下一步是什么"，而不是泛泛地被催 |
| **进度不变就不再推** | 卡住时再推只会空转烧 token —— 旧启发式的毛病 |

保留 S38 的"写操作后续跑"作为**次优先**兜底（覆盖"没用 task 工具但批量操作"的场景）。

## 2. G4–G6：反馈体系（"它在干活"看得见）

**核心洞察**：工具真在跑，但界面**几秒静默** —— 这是"像卡死/像空壳"的**主要来源**。

### 链路

```
AgentLoop（工具执行**前**）
   │  agent.activity 事件（text / tool / progress / motion）
   ▼
EventBus ──► main.py `_push_agent_activity` ──► broadcast_control
   ▼
前端 App.vue：状态行「● 3/7｜在移动文件…」（呼吸点 = 还在进行）
             + 按工具类型播一次动作（**6 秒节流**）
```

### 具体设计

| # | 内容 | 实现 |
|---|---|---|
| **G4** | 工具级活动文案 | 新模块 `yuiro/agent/activity.py`：工具 → 「正在读取目录…」；未登记回退「正在处理…」（不泄漏内部工具名） |
| **G5** | 动作与阶段联动 | 工具 → 动作索引（读/看 → TapBody#9 抬头；写/移 → #5 手部；对外操作 → #7）；**前端 6 秒节流**（读 10 个文件不该手舞足蹈 10 次） |
| **G6** | 长任务进度 | 事件带 `progress`（`3/7｜当前步骤`），前端状态行直接显示 |

### 克制的取舍

- 瞬时操作（`task_list`、`artifact_read`）**不配动作** —— 只有"看起来在干活的"工具才动；
- 状态行**回复到达即收起**（它只是"进行中"提示，不是消息）；
- 前端 5 秒无更新自动淡出，避免旧状态挂在那里。

## 3. 冒烟证据（确定性，不依赖真实模型）

```

   → 正在登记任务… | 工具=task_create | 进度='' | 动作=None
```

> 第一次写冒烟时踩了坑：测试替身只返回 `{"status":"ok"}` 而**没有真的创建任务**，

> **"测机制"要让它真的发生**，而不是把依赖 stub 掉。

## 5. Human Acceptance（待人工）

1. **状态行**：让它读一个项目/整理文件夹 → 桌宠下方应出现
   「● 正在查看目录…」，长任务时带进度「● 3/7｜在移动文件…」；
2. **动作联动**：同一次操作里最多每 6 秒动一下（不会手舞足蹈）；
3. **任务跑完**：说「帮我一步步整理 X」→ 批准 → **观察它是否逐步做完**
   （日志 `任务驱动 #N：0/2｜扫描文件`），而不是只回一句"现在开始第一步"；
4. **回复即收起**：回复云出现时状态行消失。

> 状态行的位置（`bottom: 112px`）在 `App.vue` 的 `.activity-line` 里，可按你的布局微调。

## 6. 遗留

| 项 | 说明 | 建议 |
|---|---|---|
| **任务创建仍靠模型自觉** | 引擎能"按任务驱动"，但**是否建任务**取决于模型判断（`task_plan` 的 description 引导）。整理类请求有时直接批量操作、不建任务 | 可加"多步请求预路由到 task_plan"（S40 候选） |
| 前端无进度条 UI | 目前是文字 `3/7`，没有图形进度条 | 观感优化，按需 |
| 动作语义未人工确认 | `file_read→#9`、`file_move→#5` 是按参数特征推的（S34），你 Alt+M 后可在 `motion_map` 覆盖 | 你验收时留意 |
| 活动文案是静态表 | 没有"正在读 xxx.txt"这种带参数的细化 | 需要时再扩（`activity_text` 已预留 `args`） |
