# 短曲线、客户端喜欢与随机推荐验收

日期：2026-10-26。延续现有 Runtime 和独立 UI 窗口，只改表现参数及客户端边缘适配；不进入 G1。

## 目标与验收范围

- Goal：对白连线更紧凑、可调；用户能明确喜欢/取消喜欢自己让当前角色播放的歌曲，并看到客户端日推候选。
- Scenario：双角色依次搜索并点选 Monody 原版，播放后暂停，通过结果卡喜欢，再让 Agent 恢复原收藏状态；推荐只展示，点选后才播放。
- Architecture Increment：扩展现有 speech 偏好、固定客户端 UI 操作和既有播放归属，不增加第二套播放器、Runtime 或系统执行通道。
- Tests：真实窗口/客户端/Agent验收 + 目标状态/歌曲 ID/取消/角色竞争测试 + 现有后端全量与前端检查。
- DoD：读回目标状态才报告成功；最终恢复收藏；角色切换清理；无 API/CLI 回退和歌曲版本替换。

## 交付行为

### 曲线

旧单曲线沿用高于模型的气泡 anchorY，导致嘴部到文字的垂直跨度过大。现独立按资源嘴部侧点放置文字，默认抬高 **40 DIP**、贝塞尔弯曲系数 **0.25**。不改现有闭合气泡预设。

调试台 UI → 对白 → 单曲线中新增：

- 曲线距离（文字高于嘴部）：0–240 DIP。
- 曲线弯曲程度：0–0.8，0 为控制点无额外水平弯折；端点垂直错位仍由贝塞尔平滑连接。

设置可持久化、跨窗热更新，预览与真实窗口共用计算。粗细/颜色、手动嘴部标定及原有侧向/偏移继续有效。距离控制的是**文字相对嘴部的抬高量**，不是裁断线段的固定弧长；实际长度还受模型尺寸、横向间隔与屏幕避让影响。保持文字窗不压模型，窄屏仍以避让为先。

两角色实机均测得：紧凑配置线长约 **113.1 DIP**，抬高至180并增加弯曲后约 **225.6 DIP**；这是同次实测配置对比，不是声称旧版固定长度。开放路径/无背景/穿透、字体颜色热更新、切回气泡隐藏连线、角色清理均通过。偏好测试后恢复。

### 喜欢/取消喜欢

- 结果卡当前播放器区域新增“喜欢/取消喜欢”，仅在客户端读到明确布尔状态时展示。
- 操作对象是当前角色有效 playback_id 对应的**当前歌曲 ID**，不是候选列表中任意歌曲。未知归属、另一角色、用户手动切歌均拒绝。
- Agent 新增 `netease_favorite(song_id, liked)`，使用明确目标状态，已达目标不重复点击。
- 客户端只点一次，等待连续两次匹配读回；最长60秒，等待时按钮禁用。未知结果不报告成功、不自动反向点击或重复写入，不回退 API。
- 收藏属于网易云同一账号的共享状态；双角色隔离指的是操作权限和结果归属，**不把账号收藏伪装成各角色独立歌单**。

原生实测第一次较短观察窗不足以覆盖客户端状态延迟，已改为最多60秒等待且只重读。完整原生验收写入约6.96秒、恢复28.18秒；最终确认原始未收藏状态恢复。客户端页面状态读回是验收依据，不等于取得网易云云端独立事务回执。

### 随机推荐

- `netease_recommend` 已替换为客户端日推适配器；调试台聊天菜单新增“客户端随机推荐”，也可输入 `/推荐`、`/日推`、`/recommend`，无需 LLM。
- 打开客户端推荐 → 每日推荐详情；仅读取匹配日推页面中已加载的歌曲 ID、名称、歌手，连续两次稳定后随机抽取最多6首。
- 结果卡明确标注“客户端日推 · 随机候选”；**不自动播放**。既有“从这些候选中随机播放”仍明确指当前候选集。
- 不是私人 FM/心动模式，不修改播放队列随机模式，不承诺完整分页列表或每次刷新生成全新日推。客户端自身提供个性化来源，桌宠只抽样已加载候选。

## 边界与下一步

官方客户端 UI/CDP 属版本适配，不是公开稳定 SDK。控件/页面/ID不匹配即失败。未接入私人FM、队列随机模式、歌单写入或对未归属歌曲的收藏；这些需要各自验证，不能用模糊点击或旧 API 静默代替。曲线仍用两资源静态侧向嘴部标定，不宣称逐帧嘴部追踪。
