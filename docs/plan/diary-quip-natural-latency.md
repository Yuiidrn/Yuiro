# 日记插话：自然停笔、可取消与低延迟

日期：2026-10-27。范围：既有日记陪伴轨道的局部优化，不新增 Runtime，不接入 Agent 工具循环、TTS 或持久化记忆。

## Goal / Scenario

用户开启“停笔时轻轻接一句”后，无需先点“追加段落”，在编辑区停笔即可得到短回应。继续输入时角色让出注意力，撤销、保存、退出不等待插话完成。默认仍关闭；正文是否共享记忆继续由保存选项决定，插话本身不保存。

## 修改前的问题

1. 只在 commitSegment 后计时，编辑区内的自然停顿无法触发。
2. 固定等待3.5秒，且没有根据后续键入重新判断停笔，可能用户继续写时突然返回一句旧话。
3. 插话与保存/撤销共用串行队列，云端慢响应会阻塞操作。
4. 等完整模型流结束才校验短句，没有独立生成预算；被门控跳过时无完成事件。

## Architecture Increment / 实施

| 层 | 改动 |
|---|---|
| DiaryApp | 基于输入、段落、录音/识别、审阅/保存、连接状态统一调度；停笔2/3/5秒可选；默认2秒 |
| 前端取消 | 继续键入、输入法组词、录音、保存、撤销、归档、关开关、换角及退出使待答失效；有请求时发送 `diary:quip_cancel` |
| 协议 | `engine-protocol.ts` 定义 DiaryQuipRequest；可携带未提交片段，最多向服务传最后600字；服务返回对应 request_id，沉默也完成请求 |
| WS 分发 | 插话成为连接拥有的可取消后台 task，仍注册到现有 character worker 集合；保存等日记消息维持原串行路径，收到时取消插话 |
| DiarySession | 可对临时片段回应，不追加、不落库；修订或结束后丢弃旧结果 |
| QuipService | 单请求门控，64 token输出预算、4秒生成超时；完整短句即停止并关闭流；取消向上传播，不吞取消 |
| 内容 | 更像身旁的人轻轻接话，避免评价、比较、建议和连续追问；保留情绪安全阀、最少6字、60秒输出冷却和同片段不重复 |
| 展示 | 编辑内容旁轻量短句/生成状态，沿用角色主题，不弹大面板、不主动发声 |

新阶段日志仅记录开始/首字/完成/取消/超时及耗时，不输出日记正文和供应商完整异常。固定停笔等待由3.5秒降至默认2秒，确定减少1.5秒调度等待；没有伪造一条固定回复来掩盖模型延迟。

## 剩余边界

当前录音期间主动保持安静，停止录音且识别结束后才考虑插话；尚未根据VAD的语音停顿插话，也不会用TTS抢用户说话。生成预算用于限制等待，不承诺每次云端都在4秒内成功；超时或门控不满足就安静跳过。恢复窗口/继续编辑不会自动重试相同片段。角色切换隔离沿用现有取消与修订约束，本轮未切换角色做新的真人语音验收。

## 2026-10-29：链路澄清与小修正

当前是文字旁注轨道，不经普通回复气泡/TTS。未提交文字的回应显示在编辑区下方，已追加段落的回应显示在该段下方；没有声音属于当前实现边界。追加后仍考虑最新段落，但相同文本去重可能阻止再次生成；此前编辑区回应会在追加时消失，本轮改为追加确认后转移到段落旁注。

默认停笔改为5秒，2秒仅保留为手动选择的轻快档。60秒门控限制成功生成的回应，不等于限制所有失败/沉默请求。首字日志只说明模型开始输出，不能证明已展示；新增空输出、模型沉默、超长丢弃日志及渲染端展示位置日志，不记录正文。历史实测2秒数据仍为当时配置，不代表当前默认。

若后续增加角色气泡+TTS，应复用现有表现/语音播放与取消链路，保持独立日记生成、不进普通Agent工具循环；用显式输出模式选择，不能把私密日记自动发送成普通聊天。本轮没有接通气泡/TTS，也未做新的真人语音验收。
