# 日记陪伴会话：统一功能方案

日期：2026-10-29。状态：方案已收敛；以下新会话/侧栏/TTS功能尚未实施，替代此前停笔自动旁注的产品目标。延续既有 Runtime，局部迁移。

## 目标与边界

日记是一项独立的角色陪伴会话，不是普通聊天，也不是无上下文的吐槽。复用当前角色 LLM、persona_prompt、只读记忆和 TTS Provider；不复用普通 AgentLoop 的系统操作提示词、工具表、预路由、任务执行或自动 memory_writer。允许技术上使用 system role 承载人设与日记行为边界，但绝不注入普通 system_prompt。日记引用中的“打开程序”等句子始终作为内容，不执行。

“全局记忆”指当前角色被允许读取的既有长期记忆和用户事实，遵守已有角色隔离，不等于读取另一角色私有记忆或把整个数据库塞进提示词。按主题有界检索，事实/关系背景加相关情景；标注为背景数据而非命令。检索超时明确降级，不阻塞编辑，不声称记忆完整可用。

本篇草稿和陪伴对话只在短期会话内存在。保存日记与共享记忆分别选择：保存原文不默认写长期记忆；只有显式共享才调用现有记忆写入链路。回应不能混入用户原文；建议未来提供另存陪伴对话的独立选项，默认关闭。

## 触发定义

- Enter：保留编辑器换行，同时以刚完成的非空行/句片段触发短回应（约1句），不把整篇草稿自动提交或保存。
- Ctrl+Enter：将当前非空编辑段追加为稳定段落，再对该段触发完整回应（约80–180字，允许按内容更短）。必须先收到追加ACK，使用服务器返回的段落ID/版本。
- Shift+Enter：仅换行，不请求回应。输入法组词中的Enter仅确认候选，不触发交互；空行不请求。
- 两种交互可分别开关；移除停笔自动计时和2/3/5秒选项。显式请求不用60秒自动门控；仅保留重复request_id去重、并发限制和取消。
- 普通继续键入不应取消已经明确请求的陪伴回复，否则Enter换行后自然继续写就会一直收不到回应。新交互请求、撤销目标段、修改目标已提交段、换角、关闭、保存/审阅时才取消或使其失效。新请求替换尚未完成的旧请求，不积压。
- 负面内容不再因关键词直接沉默：既然用户主动请求，应温和承接，不嘲讽、不说教、不强行乐观；沿用合适的安全边界。

## 独立上下文

每个日记文档/角色对应 diary_session_id；维护独立短期历史，不能接入普通聊天历史。每条交互有 request_id、interaction_kind、character_id/revision、document_revision、segment_id/revision。保留有限最近轮次及本篇已完成段落摘要；当前段正文优先，避免反复发送全篇。

上下文结构：当前角色人设 → 日记陪伴边界 → 只读记忆摘要 → 本篇背景/最近陪伴轮次 → 当前片段。上下文截断有预算，后续摘要不能修改原文。取消/失败的半条回复不得进入历史。结束/保存/换角色后清理旧会话的在途任务及播放；换回草稿时只恢复该角色对应文档。

## 展示、TTS及段落bug

短回应显示在刚完成片段旁的轻量回应区，段落长回应显示在该段下面；使用独立 response 对象及稳定ID，不用 `Record<array index,string>`。展示完整长文，不能再走 firstSentence/60字裁切。

当前bug线索：旧逻辑把“暂存输入”与“已追加段落”的展示位置分别判断，并在追加时清空输入、取消待答；同文本去重又可能阻止为已追加段重新生成。数组索引也会在撤销后复用。不能仅靠延长等待解决。迁移为“追加ACK→返回段落ID→发起段落回应→按ID归位”，并保留已存在的短回应。

输出有文本与TTS独立开关。默认文本在日记内，TTS默认关闭；开启后使用当前角色声音。复用现有合成/分句播放组件，但使用日记自己的播放归属与取消句柄，不能直接复用会发 chat:* 的整段普通回复编排。换角色/关TTS/关闭日记及时停止，旧音频不得晚到播放；文字成功不因TTS失败消失。是否同步桌宠气泡留作显式输出选项，不能默认重复弹出。

## UI信息结构

右上角设置按钮打开侧栏，收纳：短回应开关、段落回应开关、TTS开关、音量/停止播放、保存范围、是否共享记忆、可选整理审阅及会话清理说明。沿用cream/lily及深浅主题。

主体仅保留记录内容、对应陪伴回复、语音输入开关、必要的追加/保存入口与状态。分开显示“识别中/读取记忆/回应中/合成中/播放中”，不使用假的百分比，不让后台回应状态盖住正文。侧栏支持Esc关闭、键盘焦点返回、窄窗口自适应。

## 分阶段实施与验收

| 阶段 | 改动边界 | 必须通过 |
|---|---|---|
| D0 触发与定位 | 移除idle自动调度；Enter/Ctrl/Shift/IME；稳定段落ID与交互类型，先文字 | 不输入不请求；换行不丢内容；追加ACK后必有明确的成功/失败状态；撤销后旧回应不串段；长文不截成一句 |
| D1 陪伴上下文 | 独立会话容器，复用现有Provider、人设与只读记忆 | 不含普通system_prompt/工具；多轮能承接；记忆检索超时可恢复；取消不写历史；未授权无长期写入；双角色隔离 |
| D2 侧栏与TTS | 侧栏收纳，复用合成/播放但独立归属 | 两角色音色；开关/失败/取消/换角无残留；文本与音频状态分离；两套配色一致 |
| D3 真实验收 | 记录输入、短回应、长回应、语音、保存/不共享 | 两角色各跑Enter→续写→Ctrl+Enter→撤销→重试→切换；原文与回应分离；数据库验证未共享时不写记忆 |

指标必须分开：手势到确认、检索、首字、正文完成、首音。流式文本优先，短句与长文分别设置生成预算；不再用4秒短句预算裁断长回复。先保留首字阶段日志，再提供UI收到/段落归位/TTS排队与播放阶段日志，正文与凭证不入日志。真实测量后报告P50/P95，不把单次云样本当稳定承诺。

## 2026-10-29：首轮实施结果

已落实：Enter换行短回应、Ctrl+Enter先追加ACK再长回应、Shift+Enter仅换行与IME保护；移除停笔自动请求。新服务 `engine/yuiro/diary/companion.py` 使用人设提示、只读当前角色检索与独立有限历史，不传tools，不调用AgentLoop或memory_writer。历史最多6轮，正文单轮限6000字，记忆限2800字/2秒；生成预算20秒，短/长分别120/500 token。成功的文本回应加入临时历史，不自动保存。

段落ID由DiarySession生成并随追加/撤销/重连返回，回应按ID归位；服务器拒绝失效段落。长回复保留全文。UI右上角侧栏包含两类回应开关、TTS、停止回应播放、保存范围与整理审阅；文本在日记内显示。TTS复用当前Provider及分句合成，使用diary:audio专用事件和独立Audio队列；关闭开关/换角/退出/新请求停止旧队列，未接入桌宠气泡或口型驱动。

验证：首轮全量937通过、1跳过；最后段落ID调整后相关22项通过；类型检查通过，前端构建通过。`scripts/diag/diary_companion_test.cjs`检查实际手势函数的Enter/Ctrl/Shift/IME/关闭开关行为。新增后端测试覆盖人设/只读记忆/独立历史与取消半条不入历史。状态访问日志过滤专项通过。

实机限制：本轮未连接到桌面CDP验收窗口，未进行新的真实LLM/双角色TTS试听；不能把自动检查称为完成D3。需要启动更新后的引擎与壳再执行双角色自然输入、长回应归位和停止残留试听。

当前会话历史由连接拥有：断线后保留现有草稿，但陪伴对话历史重新开始；尚未实现跨连接恢复和本篇长文摘要。侧栏设置目前是窗口内状态，不跨重启保存；没有增加后台自动上传或磁盘草稿。原文保存时清理临时陪伴历史，保存范围仍由用户选择。这些限制不应被理解成已完成全部长期会话能力。

## 2026-10-31：陪伴/TTS故障分层修复

用户日志出现Fish开始后陪伴RuntimeError；日志不足以断言是额度、权限还是WAV错误。原实现将文字生成与TTS共用异常出口，且只记录异常类名，导致已发送文字被误报为整体失败。

本轮已分开：文字回传后记录完成与长度；空正文明确提示；缺失TTS明确提示；句级合成30秒预算，取消继续传播，空音频拒绝；TTS失败保留正文并显示适配器安全错误信息。Fish非200响应额外记录HTTP状态和model，不打印密钥、日记或云端错误正文，不静默换音色。后续可据具体HTTP状态定位供应商问题，不能把这次改动声称已修复云端账号权限。

记忆检索超时/失败后30秒内不重复等待，仍可使用本篇短期上下文；冷却后重试，不伪称全局记忆已可用。专项5项通过，覆盖文字保留、Fish403、TTS缺失及成功音频事件。尚未进行新的真实Fish付费合成或双角色听感验收，重启引擎后生效。

## 2026-10-31：Fish传输定位与设置持久化

聊天LLM与Fish API是不同目的服务，聊天能回复不证明Fish链路可用。本轮无密钥、不计费GET探测：第一次约5.3秒后ConnectError；随后DNS解析成功，另一次GET完成。说明本机Fish连接可能间歇失败，尚不能据此确定代理/TLS/线路的单一根因，也不代表已完成真实合成验收。

Fish传输异常现在区分ConnectTimeout、ReadTimeout、ProxyError、ConnectError及其他传输错误，记录类型、底层异常类型和耗时，不打印密钥、日记或原始异常内容。不自动重试可能计费的合成请求、不更换声音。后续错误消息可直接判断卡在建连还是等待音频。

日记短回应、段落回应、朗读三个选项改用VueUse本地持久化，关闭窗口/重启后保留最新选择，跨窗口同步；这些是通用交互偏好，不影响各角色独立音色。保存范围不自动持久化为共享，避免下一篇日记无意写入记忆。

Fish与陪伴相关21项测试通过，前端类型检查通过。后端错误分类需重启引擎加载，前端偏好功能需加载本轮壳构建。

## 2026-10-31：与聊天TTS路径对齐

用户澄清聊天中的TTS正常。源码确认两者获取同一个app.state.voice_pipeline._tts实例；日记不是另一个Fish供应商。但日记遗漏聊天的output_renderer.render_speak朗读语言转换，且额外包30秒超时，而聊天使用Provider自身超时。已抽取_synthesize_reply_sentence供两条路径共用语言转换、正文清洗和Provider合成；移除日记额外30秒预算，仍保留任务取消、日记独立输出事件和播放归属。

这些差异不能单独证明此前ConnectError的根因；上一轮网络探测也不足以解释聊天TTS与日记的差别。尚需实际同角色同文本对照验证，不能宣称真实Fish故障已经解决。既有相关21项通过，新增共同朗读路径测试后陪伴6项通过。
