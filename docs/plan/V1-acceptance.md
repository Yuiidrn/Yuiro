## 0. 怎么用这份清单

1. **正常用它**（说人话就行），不用刻意测；
2. 下面每类都有「✅ 正常应该是」——遇到不一样的，**记一句关键词**就够；
3. 把记录贴给我，我据此决定下一个 Sprint。
   **只有你的体验反馈才触发新 Sprint** —— 这是 v1.0 之后的工作方式。

> 建议**分 2–3 次**用（每次 20–30 分钟），比一次性跑完更容易发现"隔天还想不想用"。

## 1. 延迟（最影响"像不像人"）

### 1.1 关键指标与目标

| 指标 | 定义 | 目标 |
|---|---|---|
| **TTFA** | 你说完 → **第一个字出声** | < 1.5s |
| **ASR** | 你说完 → 识别完成 | < 400ms |
| **LLM 首 token** | 请求发出 → 第一个字回来 | < 1.0s |
| **TTS 首音频** | 开始合成 → 第一段音频就绪 | < 800ms |
| **尾段** | 长回答最后一段落地 | 不应随长度线性增长 |

### 1.2 引擎自带的 trace（S01，最有用的一份证据）

每次语音交互会打一条完整阶段时间戳，交互结束后打印：

```
voice : speech_start → speech_end → asr_final → llm_start → llm_first_token
        → llm_final → tts_start → tts_first_audio → playback_started → tts_end
chat  : turn_start → agent_start → memory_retrieve → llm_first_token
        → agent_end → reply_sent
```

**相邻两个阶段相减 = 该段耗时（毫秒）。**
把一条完整 trace 贴给我，我就能直接定位瓶颈（是识别慢、模型慢，还是合成慢）。

日志里也有即时的分段耗时：
`[voice] ASR 识别: …（xxx ms）`、`[agent] 收到 LLM 首 token（xxx ms）`。

### 1.3 该记什么

- [ ] 最慢的是哪一段？（开口前停顿 / 说完后等待 / 中间卡顿 / 尾段拖长）
- [ ] 是**首次**慢还是**每次都慢**？（首次慢 = 模型冷启动，正常）
- [ ] 长回答会不会越说越慢？
- [ ] 调用工具时会不会长时间静默（没有任何反馈）？

## 2. 交互体验

| 场景 | ✅ 正常应该是 | ⚠️ 记下来 |
|---|---|---|
| **打断**：说到一半说"等等！" | 立即静音 + 表情回中性，无残留尾巴 | 停不下来 / 停一半 / 之后对话错乱 |
| **表情**：说开心/难过的事 | 表情跟着变，**不是**一直一个表情 | 表情不变 / 变错 / 卡住不回弹 |
| **表演**：说"我终于把那个 bug 修好了！" | 调 `avatar_perform(celebrate)` 并做动作 | 不表演 / 动作突兀 / 频繁乱动 |
| **思考态**：问复杂问题 | 等待期显示思考表情 | 一直呆滞无反馈 |
| **连续对话** 10+ 轮 | 不越答越崩、人设不丢 | 开始复读 / 忘上下文 / 变"客服腔" |

## 3. 记忆（"它记得我"）

| 场景 | 怎么做 | ✅ 正常应该是 |
|---|---|---|
| 显式记忆 | 说「记住：我下周要参加算法竞赛」→ 隔一天问「我下周要干什么」 | 答得出来 |
| 琐事淡忘 | 随便聊的琐事，几天后问 | 记不清（**这是设计，不是 bug**） |
| 关系 | 问「我们认识多久了」 | 如实回答 |
| 注入自然度 | 观察回复怎么用记忆 | 自然融入，不生硬复述 |

调试：`GET /api/memory/showcase`（三通道快照）、`GET /api/memory/relationship`。

## 4. 任务与审批（"它能帮我做完一件事"）

1. 说「**帮我一步步整理下载文件夹**」→ ✅ **先给计划卡片**，不是直接动手；
2. 点「按这个来」→ 开始执行；说「按你列的做，但最后加一步清理空目录」→ 应能改写计划；
3. 故意让它做会失败的事 → ✅ 换思路重试，试不动就如实说（不无限重试）；
4. 说「**恢复刚才的操作**」→ ✅ 文件回到原样（S33 新增）；
5. 说「**你刚才改了什么**」→ ✅ 如实汇报（不猜）。

调试：`GET /api/task/list`、`GET /api/transaction/list`。

## 6. 存在感（Presence —— 目标是"别被烦到"）

- 做完一件事 → **偶尔**庆祝/关心（不是每次）；
- 长时间空闲 → 可能主动打招呼；
- `GET /api/presence/state` 看它"想不想说话"、被什么压制。

| ⚠️ 最可能的抱怨 | 调节旋钮（`[presence]`） |
|---|---|
| 太频繁 | `cooldown_s`（冷却）、`max_urgency`（打扰上限） |
| 时机不合适（专注时被打扰） | `quiet_hours`（静默时段，如 `23:00-08:00`） |
| 从不主动 | `idle_trigger_s`（空闲触发） |
