# 双角色动态轮廓命中 MVP 与原生点击验收

日期：2026-10-24。范围为当前 Electron/Live2D 前后端交互增量，不更换原生渲染框架，不推进 G1。

## Goal / Scenario / 最小增量

目标：模型透明区不再按矩形拦截鼠标，角色可见区域可交互；渐隐、功能岛、选歌/来源卡和输入框可协作；调试台能实时调参并显示遮罩。

沿用单一 Live2D WebGL 画布。在 Pixi 渲染后的 utility ticker 上，以 **8Hz** 将模型画布缩到最长边 **256px** 后读取 Alpha（实机为 192×256），不每帧读取全分辨率画面、不额外重绘模型。遮罩不包含 DOM 卡片，也不受 `.pet` 的 CSS 渐隐 opacity 影响。换模型开始清空遮罩，采样异常/无模型时透明让路，不退回整块矩形挡住桌面。

新文件：`utils/alphaHit.ts`（带阈值/距离容差的 Alpha 查询），`composables/useContourPref.ts`（跨窗口热更新偏好）。不新增 Engine Runtime、服务或外部依赖。

## 实现边界

- `Live2DCanvas.vue`：遮罩采样、绿色预览、样本耗时统计；采样完成主动通知输入判定，使鼠标不动、模型在动时也更新命中。
- `useMousePassthrough.ts`：唯一窗口穿透写入者；UI 可操作区域 > 已捕获拖动 > 渐隐 > 模型 Alpha。透明区域在指针移动/主进程坐标流更新时提前穿透，移除 mousedown 后切穿透 300ms 的旧方案。UI 打开不再使整个矩形区域都吞点击。
- `useFadeOnHover.ts`：靠近距离改用 Alpha 轮廓加距离容差；只决定 shouldFade，不再与普通穿透重复写窗口状态。
- `useBracketMenu.ts` / `usePetDrag.ts`：复用同一个轮廓命中。功能岛默认仍可通过模型停留唤出；渐隐开启时不自动从身体唤出，以免立即抵消渐隐。右下角 **⋮** 为始终保留的入口，靠近可呼出功能岛，展开时取消渐隐。旧 dwell 计时器也会复查渐隐开关。
- `App.vue`：接线并保留结果卡交互；结果卡不再跟模型一起渐隐，来源/选歌卡仍使用原点击处理。角色切换期间不接受旧轮廓命中。拖动一旦开始保持捕获语义，结果卡/聊天坞不会误触发模型拖动。
- `useElectronRelativeMouse.ts`：屏幕鼠标与窗口 bounds 都先按 Electron DIP 处理，再根据视口 CSS 尺寸换算，避免页面缩放时误把 DIP 当 CSS px。边缘判定相应使用 CSS 视口尺寸。
- 调试台 **UI → 动态轮廓命中（最小验证）**：绿色遮罩开关、Alpha 阈值 1–254、容差 0–16 CSS px，修改即时跨窗口生效，无须保存/重启。绿色显示阈值后的基础遮罩，容差是其外围的命中距离，并非修改模型纹理。默认阈值 24、容差 2px。

## 实机验收与性能

证据：[live.json](contour-artifacts/live.json)，[Hiyori 遮罩](contour-artifacts/hiyori-mask.png)、[Hotaru 遮罩](contour-artifacts/hotaru-mask.png)。两张图片为真实画布采样导出，能看见角色轮廓与腿部间隙，不是手画的轮廓。已检查导出图片。

原生点击测试不是网页 dispatchEvent：`scripts/diag/contour_acceptance.py` 创建自己拥有的 Win32 下层窗口，通过 OS 光标/鼠标输入，统计其真实 `WM_LBUTTONDOWN`。点击坐标由宠物原生窗口实际矩形与 CSS 视口换算；测试结束关闭探针、恢复鼠标、角色与偏好值。测试环境报告的 devicePixelRatio 约 1.95，未假设坐标比例为 1。

| 项目 | Hiyori | Hotaru |
|---|---|---|
| 包围盒内透明点 → 下层收到点击 | **5/5** | **5/5** |
| 实心身体点错误穿透 | **0/3** | **0/3** |
| 靠近身体触发渐隐 | 是 | 是 |
| 渐隐中遮罩仍存在 | 是 | 是 |
| 渐隐后功能岛入口呼出菜单 | open=true、faded=false | open=true、faded=false |
| 功能岛点击错误落到下层 | 0 | 0 |
| 跨窗口阈值/容差/预览热更新 | 180 / 7 / 可见 | 180 / 7 / 可见 |
| 3 秒采样窗口 | 23 次，均值 **3.82ms** | 24 次，均值 **4.89ms** |
| RAF 帧间隔 P95：暂停采样 → 开启采样 | **6.7 → 7.3ms** | **6.7 → 7.9ms** |

RAF 每组仅 1.5 秒；同模型暂停/恢复同一个采样回调比较，开启组包含预览工作，记录的是短时帧间隔，不是 GPU 完整占用或长期 P95。样本进程累计采样峰值约 8ms。8Hz 下采样的平均工作量约每秒 31–39ms，不能据此声称所有硬件无卡顿。

初轮存在坐标/探针置顶问题；中间一轮在 HMR 更新期间跑多次点击，出现 Hiyori 计数不一致，已明确归档为 `live-hmr-overlap-invalid.json`，不作为通过证据。最终测试在停止修改源码后串行跑完两角色，得到上表结果。

旧壳首次恢复出现 `ERR_NETWORK_IO_SUSPENDED`，重启了已核验的本项目 pnpm/Electron 进程树后再测；没有关闭其他应用或重启 Engine。实验最终恢复原活动角色和调参偏好，调试遮罩不会强制留在用户桌面。

## 限制 / 下一步

这是 **动态低分辨率轮廓 MVP**，不是完全无 HWND 的桌面渲染，也不是原生逐像素窗口输入区域。细发丝、低透明度材质和很窄的空隙受 256px 采样与容差影响；动作边界最多约 125ms 才更新一次。需要后续快速扫鼠标后立即点击、不同 DPI/跨屏拖动、窗口缩放/加载失败、长时间挂载测试，才能提高可靠性结论。当前只在同权限下层探针验证，不承诺管理员应用或所有捕获工具行为一致。

尚未通过真实歌曲播放回合重新验收选歌功能；卡片事件、播放 ID 路径未改，已将卡片区域列为优先交互并排除模型拖动。后续应补实际选歌、来源卡滚动与焦点的组合场景。

**保留后续拆窗方案**：模型展示窗口与回复气泡/结果（含选歌）UI 分离；统一屏幕工作区避让、DPI、焦点与角色身份边界。本轮没有实现拆窗，气泡/长卡片仍受现有窗口空间限制，不宣称已解决遮挡问题。

未 commit/push，未改角色声音/大脑配置，未移动或删除用户数据。下一步优先让用户试用两角色轮廓与渐隐手感，再决定采样精度、容差及是否需要更低层输入区域；不急于改原生渲染框架。
